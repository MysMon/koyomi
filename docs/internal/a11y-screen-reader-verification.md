# スクリーンリーダー実機検証（NVDA/VoiceOver）計画（内部）

`docs/accessibility.md` が定める WAI-ARIA パターンの実装は、Playwright + axe-core による
自動 WCAG 2.0 A/AA 検査（CI）と単体テストの `aria-*` 属性検証で担保している。
これらは DOM 構造・属性値の機械的な正しさは検証できるが、**実際のスクリーンリーダーが
どう読み上げるか**（読み上げ順序、フォーカス移動時の音声フィードバック、動的な
`aria-live` 通知のタイミング等）は検証できていない。本ドキュメントは、その実機検証の
計画とチェックリストをまとめたものである。

**現状**: この開発環境（コンテナ上の CLI）では NVDA・VoiceOver いずれの実機検証も
実行できない（NVDA は Windows + 実際のスクリーンリーダーソフトウェアが必要、
VoiceOver は macOS 実機が必要）。本ドキュメントは実施計画・チェックリストの整備までを
スコープとし、検証の実施自体は対象環境を持つ開発者・QA が本チェックリストに沿って
別途行う。

## 対象の組み合わせ

| # | OS | スクリーンリーダー | ブラウザ | 優先度 |
| --- | --- | --- | --- | --- |
| 1 | Windows 11 | NVDA（最新安定版） | Chrome（最新） | 高 |
| 2 | Windows 11 | NVDA（最新安定版） | Firefox（最新） | 中 |
| 3 | macOS（最新） | VoiceOver | Safari（最新） | 高 |
| 4 | macOS（最新） | VoiceOver | Chrome（最新） | 中 |

優先度「高」の組み合わせ（NVDA + Chrome、VoiceOver + Safari）を最初に検証し、
問題が見つかった場合はそれを解消してから優先度「中」に進む。

## 検証対象ビュー

`docs/accessibility.md`「ビューごとの ARIA パターン」に列挙された全ビューを対象とする。

- 月ビュー（`MonthView`）・複数月ビュー（`MultiMonthView`）
- 年ビュー（`YearView`）
- 週/日ビュー（`TimeGridView`）
- リソースビュー（`ResourceView`）・仮想化版（`VirtualResourceView`）
- タイムラインビュー（`TimelineView`）・仮想化版（`VirtualTimelineView`）
- リストビュー（`ListView`）・仮想化版（`VirtualListView`）

## チェックリスト

各組み合わせ（OS × スクリーンリーダー × ブラウザ）ごとに、次の項目を検証する。
apps/demo（`pnpm demo`）を検証対象として使う。

### 1. 基本的な読み上げ

- [ ] ビュー切替ボタン（`Toolbar`）の役割・状態（`aria-pressed`）が読み上げられる
- [ ] 「今日」「‹」「›」ボタンの目的が読み上げだけで理解できる
- [ ] 期間タイトル（例:「2026年7月」）が見出しとして、あるいは適切な文脈で読み上げられる
- [ ] 月ビューの日セルが「7月15日、木曜日」のように完全な日付として読み上げられ、
      「今日」の日セルには現在日である旨が伝わる（`aria-current="date"`）
- [ ] 予定要素の `aria-label`（タイトル・時刻範囲を含む）が過不足なく読み上げられる
- [ ] 「+N 件」ボタンの件数が読み上げられ、押下すると何が起きるか予測できる

### 2. キーボード操作とフォーカス移動

- [ ] Tab/Shift+Tab でツールバー → ビュー本体 → 予定の順にフォーカスが移動し、
      現在フォーカス中の要素がスクリーンリーダーで正しくアナウンスされる
- [ ] 予定にフォーカスした状態で矢印キー移動・リサイズを行った際、移動後の新しい
      日時がスクリーンリーダーで読み上げられる（`useCalendarAnnouncer` の
      `aria-live` 通知が発話されるタイミング・内容を確認する）
- [ ] Enter/Space での予定作成・確定後、作成された予定の内容が読み上げられる
- [ ] Delete/Backspace での削除後、削除された旨が `aria-live` で通知される
- [ ] フォーカスリングが仮想化ビュー（`VirtualListView` 等）のスクロール後も
      正しい要素に追従する（pinned 要素の扱いを含む）

### 3. grid パターンの妥当性

- [ ] 月・年・複数月ビューで、NVDA/VoiceOver の「テーブル読み上げモード」相当の
      機能を使った際に行・列の構造が破綻なく読み上げられる
- [ ] 週/日ビュー・リソースビューの日ヘッダー行・終日行が grid として読み上げられ、
      本文（時間軸上の自由配置領域）は grid の一部として誤読されない
- [ ] タイムラインビューの行見出し（`rowheader`）とセル（`gridcell`）の対応関係が
      読み上げから理解できる

### 4. 動的な状態変化

- [ ] ビュー切替直後、`announce: { viewChange: true }` を有効にした場合に新しい
      ビュー・基準日・表示範囲が発話される
- [ ] ドラッグでの予定作成・移動をポインタ操作で行った場合（キーボード操作ではなく）、
      スクリーンリーダー利用者が結果を把握できる手段があるか（`aria-live` 通知の
      有無・タイミング）を確認する
- [ ] 繰り返し予定の編集スコープ確認（`this`/`thisAndFollowing`/`all`）を伴う
      操作で、適用結果が読み上げで確認できる

## 問題の記録方法

検証で見つかった問題は、本チェックリストの該当項目に発見日と概要を追記した上で、
再現手順を明記した GitHub Issue（`bug` ラベル）として起票する。修正した場合は
`CHANGELOG.md` に記載し、本チェックリストは次回の回帰検証に備えてそのまま残す。
